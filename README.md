# Памагочи — математика с открытиями

Единое статическое приложение для первоклассника: **7 мини-уроков, 28 заданий**, карта занятий, подсказки, открытия-звёзды и сохранение ответов. Все прежние 16 заданий и 12 заданий лаборатории сохранены. Уроки открыты сразу; нет таймеров, оценок и штрафов за ошибки.

## Запуск и публикация

Откройте `index.html` или запустите необязательный сервер из корня:

```sh
python3 -m http.server 8775 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8775/`. Для сохранения используйте один адрес и браузер; HTTP предпочтительнее `file://`. Node.js, сборка, backend и внешние CDN для работы сайта не нужны.

GitHub Pages: публиковать корень репозитория. Все пути относительные, поэтому сайт работает под `/pamagochi_school/`; допустима также отдельная публикация `pamagochi_school_site/`. `lab.html` перенаправляет в объединённый сайт. Коммит и публикация не выполняются автоматически.

## Архитектура

- `index.html` — совместимый вход в приложение.
- `pamagochi_school_site/index.html` — единственный интерфейс: карта, урок, диалоги.
- `assets/app.js` — hash-навигация, общий прогресс, продолжение и сброс текущего урока.
- `assets/app.css` — дизайн интерфейса и адаптивная сетка.
- `assets/lessons.js` — каталог уроков: стабильный ID, название, навык, адаптер и задания.
- `assets/exercise-theme.css` — единые стили карточек заданий, кнопок и обратной связи.
- `assets/lessons/foundations.js` и `.css` — первые 16 упражнений, их проверка и сохранение.
- `assets/lessons/laboratory.js` и `.css` — 12 упражнений лаборатории с декларативными описаниями `title`, `intro`, `hint`, `render`, `expected` / `custom`.
- `assets/mascot.svg` — оригинальный робот-помощник, вынесенный из лаборатории.

Пути `assets/` выше указаны относительно `pamagochi_school_site/`.

Два адаптера монтируются в **Shadow DOM**, не в iframe: старые одинаковые ID и классы не конфликтуют. У приложения одна навигация, одна карта и общий прогресс. Общий CSS загружается после CSS адаптера. Vanilla JavaScript выбран намеренно: интерактивность уже есть, тяжёлый фреймворк и обязательная сборка сейчас не дают необходимого преимущества. Существующие математические проверки не переписаны ради смены технологий.

Контракт адаптера: `mount(root, onProgress)` возвращает `show(...)`, `reset(taskIds)`, `solved()`. `onProgress(ids, storageOK)` вызывается при изменении результатов. ID задания уникален внутри адаптера; в каталоге идентичность — пара `engine + taskId`.

## Как добавить урок по новым фотографиям

1. Определить навык, не копируя текст, иллюстрации и композицию учебника.
2. Придумать 4 оригинальных задания немного сложнее стандартных: два признака, два шага, несколько ответов или поиск правила.
3. Добавить задания в существующий адаптер или отдельный адаптер с контрактом выше. При новом адаптере подключить скрипт в HTML, контейнер и регистрацию в `app.js`.
4. Добавить запись в `assets/lessons.js` со стабильным `id`, `engine`, `tasks`, названием и навыком. Карточка, ссылки вперёд/назад и общий TOTAL вычисляются автоматически.
5. Если расширяется лаборатория, обновить её `TOTAL` и ограничения загрузки сохранений. Это адаптер существующих 12 заданий, а не универсальный генератор.
6. Не менять ID и порядок уже сохраняемых полей первых 16 заданий без миграции: их формат v1 хранит массивы значений/выборов/мест. Для новых больших групп предпочтителен отдельный адаптер со стабильными ключами ответов.
7. Проверить пустой, частичный, неверный и верный ответ, изменение после успеха, повтор, подсказку, сохранение, перезагрузку, сброс, клавиатуру и мобильную ширину. Каждое проверяемое значение должно быть доступно в UI.

Фото передаются в чат; загрузчика фотографий и автоматической генерации на сайте нет.

## Сохранение и совместимость

- `pamagochi-lab-v1`: прежние ответы и проверенные результаты лаборатории читаются без смены ключа.
- `pamagochi-foundations-v1`: ответы, сортировка и результаты первых 16 заданий (раньше не сохранялись).
- `pamagochi-last-lesson`: последний открытый урок для кнопки продолжения.

Изменение ответа снимает отметку до проверки. При восстановлении сохранённые отметки проверяются заново. Сброс с подтверждением затрагивает **только открытый урок**, остальные результаты сохраняются. При запрете хранилища сайт работает в памяти и предупреждает, что страницу нельзя закрывать для сохранения текущей работы. Прогресс не отправляется на сервер и не синхронизируется между устройствами.

## Проверки

Только для разработки: Node.js, Playwright и Chromium. Сервер должен работать на порту 8775.

```sh
node tests/app.browser.cjs
node tests/lab.browser.cjs
# При внешней установке Playwright: NODE_PATH=/path/to/node_modules node ...
```

`APP_URL` / `LAB_URL` переопределяют URL приложения. `LAB_SCREENSHOTS` задаёт папку снимков лаборатории. Тесты используют изолированные браузерные контексты, не пользовательские сохранения.

Покрытие: все 28 правильных решений; пустые, неверные и частичные ответы; подсказки, повторы, редактирование решённого задания; раздельная проверка чисел и знака; явный ноль углов; сохранение сортировки и ответов; отмена и изолированный сброс; клавиатура; семь маршрутов; ширины 1440, 390 и 320; повреждённое/недоступное хранилище; отсутствие JS-ошибок. Мобильные проверки — эмуляция Chromium, не физический телефон.
