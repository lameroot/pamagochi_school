# AGENTS.md

## Что это за проект

Мы делаем интерактивный учебный сайт для ребёнка 1-го класса по математике.

Проект называется `pamagochi_school`.

Основной сценарий использования:
- родитель открывает сайт ребёнку;
- ребёнок самостоятельно решает задания в браузере;
- задания интерактивные: выбор ответа, сортировка, счёт, поиск закономерности, логические таблицы;
- после каждого задания есть проверка и понятная обратная связь;
- есть подсказки и общий прогресс.

Проект публикуется как статический сайт через GitHub Pages.

Репозиторий:
`lameroot/pamagochi_school`

Планируемый публичный адрес:
`https://lameroot.github.io/pamagochi_school/`

---

## Главная цель проекта

Не просто повторить школьные упражнения, а сделать ребёнку интересную интерактивную тренировку по темам 1-го класса.

Мы ориентируемся на темы из учебника Л. Г. Петерсон «Математика», но не копируем страницы буквально.

Задача проекта:
1. посмотреть, какой навык тренирует упражнение в учебнике;
2. придумать новое оригинальное упражнение на тот же навык;
3. сделать его интерактивным;
4. сделать чуть сложнее обычного задания из тетради;
5. сохранить уровень, понятный первокласснику.

## Что мы уже изучали по учебнику

По фотографиям страниц были выделены такие темы:

### Свойства предметов
- цвет;
- форма;
- размер;
- материал;
- количество;
- назначение;
- расположение.

Примеры навыков:
- найти общий признак у предметов строки;
- найти общий признак у предметов столбца;
- выбрать предмет той же формы, но другого цвета;
- классифицировать предметы по нескольким признакам.

### Плоские и объёмные фигуры

Плоские:
- круг;
- квадрат;
- прямоугольник;
- треугольник;
- овал и другие простые формы.

Объёмные:
- шар;
- куб;
- параллелепипед;
- цилиндр;
- конус;
- пирамида.

Навыки:
- отличать плоскую фигуру от объёмной;
- сопоставлять геометрическую фигуру и предмет такой же формы;
- понимать разницу между кругом и шаром, квадратом и кубом и т. п.

### Счёт и сравнение

Навыки:
- считать предметы по цвету;
- считать по размеру;
- считать общее количество;
- сравнивать количества знаками `<`, `=`, `>`.

### Закономерности

Навыки:
- продолжить ряд;
- заметить чередование цветов;
- заметить чередование форм;
- одновременно отслеживать цвет и форму;
- найти место, где правило нарушено;
- определить недостающий элемент.

### Логические таблицы

Навыки:
- понять правило по строкам;
- понять правило по столбцам;
- определить, какой элемент должен быть в пустой клетке.

### Пары

Навыки:
- соединить предметы по общему цвету;
- соединить фигуры по форме;
- объяснить, почему предметы образуют пару.

## Какой уровень сложности нам нужен

Самые простые задания вроде:

> «Нажми на круг»

нам уже не подходят.

Нужны задания немного сложнее.

Хороший уровень:
- выбрать сразу по двум признакам;
- найти несколько правильных вариантов;
- сначала понять правило, потом применить;
- сравнить строку и столбец;
- найти ошибку в последовательности;
- определить недостающий элемент;
- сначала сосчитать, затем сравнить;
- выполнить 2 связанных шага.

Пример хорошего задания:

> Формы идут: круг, квадрат, треугольник.  
> Цвета чередуются: красный, синий.  
> Выбери следующие два элемента.

Это именно тот уровень, который нам нужен.

## Важные исправления, которые уже обсуждались

Эти проблемы уже возникали, поэтому будущий агент не должен их возвращать.

### Задание 10 — счёт кругов

Ребёнок правильно ввёл:
- красных: 2;
- жёлтых: 4;
- больших: 6;
- маленьких: 9;
- всего: 15.

Но интерфейс показывал ошибку, если не был выбран знак сравнения.

Правильное поведение:
- отдельно проверять числа;
- отдельно проверять знак;
- если числа верны, не писать «пересчитай всё»;
- сообщать, что осталось выбрать или исправить только знак.

---

### Задание 15 — нарушение последовательности

Исходный вариант позволял найти неправильную бусину, но не позволял явно указать, чем её заменить.

Нужно, чтобы ребёнок мог выполнить все части задания:
1. выбрать место ошибки;
2. указать правильный цвет вместо ошибочной бусины;
3. выбрать продолжение последовательности.

Главное правило:

**Нельзя проверять значение, которое пользователь физически не может указать через интерфейс.**

---

### Задание 16 — флажки

Флажки справа были почти невидимы, потому что белая фигура находилась на белом фоне.

Нужно:
- всегда делать контур;
- использовать лёгкую серую/цветную заливку;
- визуально чётко различать:
  - треугольный флажок;
  - прямоугольный;
  - флажок с выемкой.

## Как должен выглядеть интерфейс

Стиль:
- светлый;
- добрый;
- современный;
- школьный, но не слишком «детсадовский»;
- крупные элементы;
- синие акценты;
- карточки со скруглением;
- понятные кнопки.

Главные кнопки:
- `Проверить`;
- `Подсказка`.

После проверки ребёнок должен получить короткий и понятный ответ.

Пример:

Хорошо:
> Все числа верны! Теперь выбери знак между большими и маленькими кругами.

Плохо:
> Ошибка.

## Интерактивность

Используем:
- выбор одной карточки;
- выбор нескольких карточек;
- ввод числа;
- выбор знака;
- dropdown/select, если это удобно;
- drag & drop;
- логические матрицы;
- последовательности.

Важно:

Drag & drop не должен быть единственным способом управления.

На телефоне и планшете должен работать вариант:

1. нажать предмет;
2. нажать место, куда его нужно положить.

## Текущий принцип устройства заданий

Каждое задание — отдельный блок:

```html
<section class="task" id="t10">
```

Есть:
- текст;
- интерактивная часть;
- кнопка проверки;
- подсказка;
- feedback.

Для проверки обычно используется функция:

```js
check10()
```

После проверки вызывается общий механизм:

```js
mark(10, true, "Сообщение")
```

или:

```js
mark(10, false, "Сообщение")
```

Правильно решённые задания сохраняются в `solved`.

Есть общий прогресс:

```js
TOTAL
```

Если добавляется новое задание, `TOTAL` нужно обновлять.

## Очень важное правило при изменении задания

Перед написанием проверки сначала ответить на вопрос:

> Может ли ребёнок через текущий интерфейс указать всё, что проверяет JavaScript?

Если нет — сначала исправить UI.

Не создавать скрытых условий.

## Как создавать новые задания

### Шаг 1. Определить навык

Например:

> Найти закономерность одновременно по форме и цвету.

### Шаг 2. Создать новый пример

Не копировать конкретную страницу учебника.

### Шаг 3. Сделать ответ однозначным

Если правильных вариантов несколько, в тексте написать:

> Выбери все подходящие ответы.

### Шаг 4. Создать понятную интерактивность

Ребёнок сразу должен понимать, что нажимать.

### Шаг 5. Добавить проверку

Проверка должна учитывать:
- пустой ответ;
- частично правильный;
- полностью правильный;
- неправильный.

### Шаг 6. Добавить полезную подсказку

Подсказка объясняет способ решения, а не просто выдаёт ответ.

## Изображения

Для точных геометрических заданий лучше использовать:
- CSS shapes;
- SVG;
- собственные изображения.

Emoji можно использовать для обычных предметов:
- яблоко;
- мяч;
- книга;
- подарок;
- игрушки.

Но нельзя использовать emoji, если форма изображения критична для правильного математического ответа и на разных устройствах может выглядеть по-разному.

## Авторские права

Фотографии страниц учебника используются только для понимания учебной темы.

Не надо:
- копировать страницу учебника;
- повторять её композицию один в один;
- копировать персонажей;
- копировать иллюстрации;
- дословно переносить большой текст.

Нужно создавать новые задания на тот же навык.

## Что хотим делать дальше

Следующие полезные направления развития проекта:

### 1. Добавлять новые уроки

Не делать одну гигантскую страницу на сотни упражнений.

Желательно постепенно разделить сайт на уроки или темы:

- свойства предметов;
- плоские фигуры;
- объёмные фигуры;
- закономерности;
- счёт;
- логические задачи.

### 2. Генерация новых вариантов

В перспективе некоторые задания можно генерировать случайно:
- менять цвета;
- менять порядок фигур;
- менять количество объектов;
- генерировать новую последовательность.

Чтобы ребёнок мог проходить упражнение несколько раз.

### 3. Сохранение результата

В будущем можно использовать `localStorage` для:
- сохранения прогресса;
- сохранения последнего урока;
- количества решённых задач.

Backend для этого не нужен.

### 4. Режимы сложности

В перспективе:
- обычный;
- сложнее.

Но текущий основной уровень — «чуть сложнее стандартного упражнения первого класса».

### 5. Более интересная подача

Можно добавлять:
- короткие миссии;
- звёзды за задания;
- небольшой итог урока;
- персонажа-помощника.

Но игровой слой не должен отвлекать от математики.

## Критерий хорошего результата

Новое задание считается хорошим, если:

- первоклассник понимает инструкцию;
- ответ можно реально выбрать или ввести;
- есть однозначное правило;
- оно развивает мышление, а не только узнавание картинки;
- интерфейс не ломается на телефоне;
- неправильный ответ получает полезное объяснение;
- правильный ответ действительно принимается системой.
